# فاز ۵ — داشبورد مدیریتی و گزارش‌ها

## دامنه
- `GET /api/v1/dashboard` (KPI مشتریان، سرنخ‌ها، فرصت‌ها، فعالیت‌ها؛ هر بخش فقط با مجوز خواندنِ همان ماژول؛ `scope=all` نیازمند `reports.read`).
- `GET /api/v1/reports/sales-performance` و `.csv` (مجوزهای `reports.read` + `reports.export`، ثبت `report.exported` در Audit، خنثی‌سازی فرمول در CSV).
- رابط: کاشی‌های KPI، قیف فروش، روند فروش موفق (روزانه/ماهانه شمسی)، فعالیت‌ها، سرنخ‌ها، جدول عملکرد کارشناسان، فیلتر بازه و دامنه، خروجی CSV.
- مبالغ: ریال صحیح (BigInt، رشته در API)، نمایش به تومان؛ زمان UTC و روزبندی تهران.
- نمودارها بر اساس قواعد dataviz: یک سری = یک رنگ، بدون محور دوگانه، نمای جدولی برای هر نمودار، tooltip با hover/focus.

## شواهد راستی‌آزمایی (CI روی `phase-5/dashboards`)
| مورد | نتیجه |
|---|---|
| verify (format، typecheck، build) | موفق |
| تست‌های API با دیتابیس | ۷۵ موفق، ۱ رد‌شده (قبلی)، از جمله ۸ تست `reports.e2e` |
| تست‌های contracts / i18n / web | ۱۴ / ۹ / ۱ موفق |
| migration-drift | موفق (بدون تغییر schema) |
| audit وابستگی‌ها | موفق |
| e2e Playwright + axe | ۹ از ۹ موفق، شامل سناریوی داشبورد |

## اصلاحات در مسیر
- دیالوگ فعالیت پیش از refetch بسته می‌شود (پایداری e2e).
- انتخاب‌گرهای فیلتر داشبورد `aria-label` صریح دارند.

## محدودیت‌های شناخته‌شده
- دسترسی سطر‌به‌سطر (مالک/تیم) هنوز اعمال نشده؛ `scope=all` فقط بر پایه نقش است.
- گزارش‌های زمان‌بندی‌شده/ایمیلی نیازمند worker هستند (فاز بعد).
