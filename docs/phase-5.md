# فاز ۵ — پیشنهاد و قرارداد (طبق سند معماری)

## دامنه

محصولات، پیش‌فاکتور (نسخه‌بندی، شماره‌گذاری، چرخه ارسال/پذیرش/رد)، قرارداد (ایجاد از پیش‌فاکتور پذیرفته‌شده، فعال‌سازی، تکمیل، فسخ) و خروجی چاپ/PDF. جزئیات تصمیم‌ها: [ADR 0006](adr/0006-quotes-contracts.md).

## API

`/products`، `/quotes` (`:id/versions`، `:id/status`، `:id/revise`)، `/contracts` (`:id/activate|complete|terminate`). مجوزها: `products.*`، `quotes.read|write|delete`، `contracts.read|write`. هر Endpoint تست مجوز دارد.

## UI

صفحات محصولات، فهرست/ساخت/جزئیات پیش‌فاکتور (پیش‌نمایش زنده مبلغ، تاریخ شمسی، نسخه‌ها، چاپ)، فهرست/جزئیات قرارداد، لینک «پیش‌فاکتور جدید» در پرونده مشتری.

تست‌های دیتابیس: مجوز هر Endpoint (۴۰۱/۴۰۳)، محاسبه دقیق مبالغ، شماره‌گذاری پیوسته در هم‌زمانی، رد ورودی نامعتبر و فیلد ناشناخته، CHECKهای دیتابیس، قفل شدن پس از ارسال، نسخه‌بندی، تنها یک نسخه‌ساز در هم‌زمانی، انقضا، یکتایی قرارداد، چرخه قرارداد، حذف فقط پیش‌نویس، رکوردهای Audit.

## محدودیت‌های شناخته‌شده

- PDF از چاپ مرورگر است، نه تولید سمت سرور.
- مجوز سطح رکورد (مالک/تیم) هنوز اعمال نمی‌شود؛ هر کاربر با `quotes.read` همه پیش‌فاکتورهای سازمان را می‌بیند.
- پیوند پیش‌فاکتور به مخاطب در API هست ولی فرم انتخاب مخاطب ندارد.
- ارسال پیش‌فاکتور به ایمیل مشتری نیازمند Worker/صف است (فاز ۷).
