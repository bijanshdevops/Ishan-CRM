## محدودیت CSP

برای اعمال nonce صفحات به‌صورت پویا رندر می‌شوند (`dynamic = 'force-dynamic'`)؛ برنامه پس از ورود است و پیش‌رندر ایستا کاربردی نداشت.

## الزامات استقرار (ADR 0023)

- `TRUST_PROXY` را فقط با آدرس/تعداد پراکسی‌های معتبر پر کنید؛ API نباید مستقیم از اینترنت در دسترس باشد.
- پورت worker (`/metrics`، `/health/live`) را به شبکه‌ی داخلی/مانیتورینگ محدود کنید.
- `ENCRYPTION_KEY` و گذرواژه‌ی ادمین را مقدار تازه بدهید؛ مقادیر `compose.dev.yml` عمومی‌اند.
- آدرس IP کلاینت (ADR 0024): پراکسی Next آدرس مستقیم کلاینت را به API نمی‌رساند، فقط `X-Forwarded-For` ورودی را عبور می‌دهد.
  reverse proxy جلوی وب باید این هدر را **بازنویسی** کند (nginx: `proxy_set_header X-Forwarded-For $remote_addr;`، نه `$proxy_add_x_forwarded_for`)
  و `TRUST_PROXY=1` باشد. بدون آن، IP ثبت‌شده در ممیزی و نشست‌ها و کلید محدودکننده‌ها آدرس کانتینر وب است.
- پشتیبان (ADR 0025): کپی بیرونی از میزبان، گذرواژه‌ی رمزنگاری جدا از پشتیبان، نقش دیتابیس جدا برای سرویس `backup` و تمرین دوره‌ی بازیابی با ثبت زمان (`docs/backup-restore.md`).
