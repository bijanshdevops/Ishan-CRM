# زنجیره تأمین: SBOM و اسکن آسیب‌پذیری

هر اجرای CI (جاب `supply-chain (SBOM + Trivy)`) ایمیج‌های تولید `api` (هدف `runner`) و `web` را می‌سازد و دو کار می‌کند.

## SBOM

- برای هر ایمیج یک فایل CycloneDX (`ishan-api.cdx.json`، `ishan-web.cdx.json`) با Trivy ساخته می‌شود.
- فایل‌ها به‌عنوان artifact با نام `sbom-<commit>` ۹۰ روز نگه داشته می‌شوند (تب Actions ← اجرای CI ← Artifacts).
- SBOM فهرست بسته‌های سیستم‌عامل (Alpine، Chromium) و بسته‌های npm داخل ایمیج را دارد؛ برای ممیزی یا بررسی یک CVE تازه کافی است فایل را با ابزاری مثل `trivy sbom` یا `grype sbom:` اسکن کنید.

## اسکن آسیب‌پذیری

- Trivy (`aquasec/trivy:0.58.1`، نسخه‌ی ثابت) هر دو ایمیج را اسکن می‌کند.
- جاب فقط وقتی **رد می‌شود** که آسیب‌پذیری با شدت HIGH یا CRITICAL **و دارای نسخه‌ی اصلاح‌شده** (`--ignore-unfixed`) پیدا شود؛ یافته‌های بدون اصلاح گزارش نمی‌شوند تا CI بی‌دلیل قرمز نشود.
- هنگام شکست، فهرست یافته‌ها (ایمیج، CVE، شدت، بسته، نسخه‌ی فعلی ← نسخه‌ی اصلاح‌شده) به‌صورت کامنت روی commit و annotation ثبت می‌شود.

## برخورد با یافته‌ها

1. **ارتقا** (ترجیح): نسخه‌ی بسته یا ایمیج پایه را بالا ببرید (Dependabot همین کار را برای npm، Actions و Docker پیشنهاد می‌دهد).
2. **پذیرش موقت**: فقط اگر ارتقا ممکن نیست، CVE را با دلیل و تاریخ بازبینی در `.trivyignore` بنویسید؛ هدف، فهرست خالی است.

## محدودیت‌ها

- اسکن فقط وابستگی‌های شناخته‌شده را می‌یابد؛ جایگزین بازبینی کد، pen-test یا `pnpm audit` (که جداگانه در CI اجرا می‌شود) نیست.
- پایگاه آسیب‌پذیری Trivy در هر اجرا به‌روز می‌شود؛ بنابراین یک commit قدیمی ممکن است بعداً با اجرای دوباره قرمز شود، که رفتار درست است.
