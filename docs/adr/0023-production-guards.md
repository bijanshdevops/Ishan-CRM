# ADR 0023 — قفل‌های امنیتی پیکربندی production

وضعیت: پذیرفته‌شده

## زمینه

چک امنیتی (مهر ۱۴۰۵) سه شکاف عملیاتی نشان داد:

1. `trustProxy: true` بی‌قیدوشرط بود؛ اگر API بدون پراکسی معتبر در دسترس باشد، هدر `X-Forwarded-For` جعلی
   محدودکننده‌های نرخ مبتنی بر IP را بی‌اثر می‌کند.
2. کلید رمزنگاری و گذرواژه‌ی ادمین در `deploy/compose.dev.yml` عمومی‌اند، ولی چیزی جلوی استفاده‌ی آن‌ها در
   production را نمی‌گرفت.
3. `/metrics` روی worker بدون احراز هویت است و روی `0.0.0.0` گوش می‌دهد.

## تصمیم

- متغیر `TRUST_PROXY` (`true`، `false`، تعداد hop یا فهرست CIDR با کاما) به Fastify داده می‌شود. در production
  **اجباری** است؛ بیرون از production پیش‌فرض `true` می‌ماند.
- در production، کلید رمزنگاری و گذرواژه‌ی ادمین dev باعث شکست راه‌اندازی می‌شود، مگر `ALLOW_DEV_SECRETS=true`
  (فقط در compose.dev.yml که حالت production را با رازهای عمومی اجرا می‌کند).
- پورت worker (`WORKER_PORT`) و `/metrics` باید فقط روی شبکه‌ی داخلی در دسترس باشد؛ در compose publish نشده و
  در استقرار واقعی باید با NetworkPolicy/فایروال محدود شود.
- وابستگی `js-yaml` با override به ‎≥ 5.4.1 رفع شد (GHSA-r3ph-w7gj-g6xm).

## پیامدها

- استقرارهای موجود production باید `TRUST_PROXY` را اضافه کنند، وگرنه API بالا نمی‌آید (خطای روشن می‌دهد).
- آستانه‌ی `pnpm audit` در CI همچنان `high` است.
