# ADR 0019 — متریک صف‌ها (Prometheus)

وضعیت: پذیرفته‌شده

## زمینه

ADR 0010 و 0011 هشدار روی صف‌های عقب‌مانده و نرخ شکست کارها را به متریک‌ها موکول کردند. امروز اگر Worker
از کار بیفتد یا یک صف انباشته شود، تنها نشانه شکایت کاربر است (اعلان نرسیده، وب‌هوک نرفته، ایمیل نرفته).

## تصمیم

- **نقطه‌ی انتشار: سرور HTTP داخلی Worker** (`WORKER_PORT`) با مسیر `GET /metrics` در کنار `/health/live`. صف‌ها
  در Redis مشترک‌اند، پس یک منبع کافی است و با چند نمونه‌ی API متریک تکراری ساخته نمی‌شود. API بدون Redis هم
  بالا می‌آید و نباید سطح تازه‌ای بگیرد.
- **فرمت:** متن Prometheus نسخه‌ی 0.0.4، دست‌نویس. سه خانواده‌ی ساده وابستگی تازه نمی‌ارزد؛ OpenTelemetry
  Metrics در بخش مشاهده‌پذیری جداگانه می‌آید و این نام‌ها را می‌توان بی‌تغییر منتقل کرد.
- **سری‌ها:**
  - `ishan_queue_jobs{queue,state}`: تعداد کارها به تفکیک `waiting، active، delayed، prioritized، failed، completed، paused`
  - `ishan_queue_oldest_waiting_age_seconds{queue}`: سن قدیمی‌ترین کار منتظر شروع (۰ اگر صف خالی است)؛ بهترین
    نشانه‌ی «Worker کار را برنمی‌دارد»
  - `ishan_worker_jobs_processed_total{queue,result}`: شمارنده‌ی کارهای پایان‌یافته در همین فرایند (`completed|failed`)
  - `ishan_worker_up`: ۱ وقتی همه‌ی workerهای فرایند در حال اجرایند
  - `ishan_queue_scrape_ok`: ۰ وقتی خواندن یکی از صف‌ها از Redis شکست خورد (آن صف از خروجی حذف می‌شود، نه صفر)
- **قرارداد خطا:** خطای Redis حین scrape کل درخواست را نمی‌شکند؛ فقط `scrape_ok=0`. خطای غیرمنتظره‌ی
  تولید متریک `500` بدون جزئیات می‌دهد.
- **امنیت:** فقط شبکه‌ی داخلی؛ پورت Worker در compose منتشر نمی‌شود و نباید پشت Ingress عمومی برود. مقدار
  برچسب‌ها ثابت و از نام صف‌هاست (بدون داده‌ی مشتری یا شناسه‌ی کار). احراز هویت ندارد، همان‌طور که `/health/live` ندارد.
- **cardinality:** برچسب‌ها فقط `queue` (۵ مقدار) و `state` (۷ مقدار) و `result` (۲ مقدار) هستند.

## هشدارهای پیشنهادی (نمونه)

- `ishan_queue_oldest_waiting_age_seconds{queue="events"} > 300` برای ۵ دقیقه: Worker کار برنمی‌دارد یا کند است
- `increase(ishan_worker_jobs_processed_total{result="failed"}[15m]) > 0`: شکست کار
- `ishan_queue_jobs{state="failed"}` رو به رشد، `ishan_worker_up == 0`، `ishan_queue_scrape_ok == 0`

## پیامدها

- شمارنده‌ی پردازش‌شده با ری‌استارت Worker صفر می‌شود (رفتار استاندارد counter؛ `rate()` آن را مدیریت می‌کند).
- صف `campaign-emails` هم در خروجی هست (عمق و سن)، حتی اگر کانال ایمیل خاموش باشد و Worker نداشته باشد؛
  آنجا `waiting` رو به رشد نشانه‌ی کاری است که برداشته نمی‌شود.
- Tracing و سایر متریک‌های HTTP در بخش OpenTelemetry جدا می‌آید.
